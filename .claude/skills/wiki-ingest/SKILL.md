# Wiki Ingest

將新的文字、檔案、連結或其他來源整理進知識庫。

## 步驟

1. **讀取來源**

   讀取本次要收錄的內容，辨識來源包含的主要資訊。

   只有當資訊不足且會影響收錄方式時，才向使用者釐清。

2. **決定歸屬**

   先讀取 `2-wiki/index.md`，了解目前已有的主題與專案。

   依來源內容判斷：

   - 屬於既有 topic → 更新適合的既有頁面，或在該 topic 建立新頁面。
   - 屬於進行中的 project → 更新或建立 `2-wiki/projects/active/<project-name>/` 下的頁面。
   - 沒有適合的既有歸屬 → 建立新的 topic；只有內容本身具有明確目標或終點時才建立 project。
   - 同時涉及多個領域 → 選擇最主要的歸屬，其餘透過交叉引用連結，不為相同資訊建立重複副本。

   歸屬確定後，再決定頁面名稱、是否更新既有頁面，以及是否需要建立新的頁面。

3. **報告收錄計畫**

   正式寫入前，向使用者說明：

   - 預計收錄至哪個 topic 或 project；
   - 預計建立或修改的 wiki 頁面；
   - 原始來源預計保存的位置；
   - 必要的交叉引用；
   - 預計整理進 wiki 的內容概要。

   取得使用者確認後才執行寫入。

   若使用者要求調整方案，依新的方案重新確認。

4. **保存原始來源**

   讀取：

   ```text
   .claude/specs/raw-lifecycle.md
   ```

   依規格將需要保留的原始來源存入 `1-raw/`，保留來源原貌。

5. **寫入 Wiki**

   建立或修改 `2-wiki/` 頁面前，讀取：

   ```text
   .claude/specs/wiki-page.md
   ```

   依其規格處理頁面格式、命名與交叉引用。

   整理來源時可以摘要、重組與整合資訊，但：

   - 不捏造來源沒有提供的事實；
   - 不把推論寫成來源本身的結論；
   - 需要加入分析或推論時，應與來源內容清楚區分。

   若已有相關 wiki 頁面，優先更新既有知識，而不是建立內容高度重複的新頁面。

6. **建立必要的交叉引用**

   檢查本次新增或修改的內容與既有 wiki 頁面之間是否有實際關聯。

   有明確關聯時建立 Wikilink；沒有適合的關聯時，不為了增加連結數量強行建立連結。

   只修改本次 Ingest 確實需要同步的頁面。

7. **更新索引**

   若本次 Ingest：

   - 建立新的 topic；
   - 建立新的 project；
   - 建立需要被索引的新頁面；
   - 或使既有索引描述不再準確；

   則讀取：

   ```text
   .claude/specs/wiki-index.md
   ```

   依規格同步更新 `2-wiki/index.md`。

8. **處理圖片與附件資訊**

   若來源包含圖片或附件：

   - 承載理解來源所需資訊時，應納入內容判讀；
   - 純裝飾、版面用途或與知識內容無關時，不需要額外分析。
