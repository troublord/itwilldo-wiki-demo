# wiki-query 查詢報告格式

不論這次查到或查不到答案，都要附上這份報告。呈現順序固定為：**相關主題 → 查詢紀錄 → 答案（或查無結果訊息）**。

## 查到時

```
---
【相關主題】
- <主題或專案名稱>（若為 project，標記進行中／已封存）

【查詢紀錄】
- Grep：模式「XXX」於 <範圍>，命中：[[頁面A]]、[[頁面B]]、[[頁面C]]
- Read（採用）：[[頁面A]]、[[頁面B]]
- Read（未採用，判斷不相關）：[[頁面C]]

【答案】
（綜合作答內容，各論點附來源）
```

- 【相關主題】依【查詢紀錄】裡「採用進答案」的頁面路徑，依下方「主題判準」對應到主題名稱，去重後列出；不含「未採用」的頁面，也不追蹤頁面中的 wikilink。
- 【查詢紀錄】列出這次真的執行過的 Grep 呼叫（模式、範圍）與其原始命中檔名，以及真的 Read 過的頁面——這是工具呼叫的實際紀錄，不是事後改寫的摘要描述。Read 過的頁面依有沒有拿來組成答案，分成「採用」與「未採用，判斷不相關」兩行，不得只列採用的、漏記 Read 過但沒用上的頁面。

### 主題判準

依頁面路徑對應到哪一層當主題名稱，不得自行發明分類方式：

- `topics/<主題名稱>/...` → 主題＝`<主題名稱>`
- `projects/active/<專案名稱>/...` → 主題＝`<專案名稱>`（標記進行中）
- `projects/archive/<專案名稱>/...` → 主題＝`<專案名稱>`（標記已封存）
- 不屬於以上任何路徑（例如 `2-wiki/` 根目錄的 `index.md`）→ 主題＝「wiki 頂層」

## 查不到時

```
---
【查詢紀錄】
- Grep：模式「XXX」於 <範圍>，命中：[[頁面A]]（判斷不相關）
- Read（未採用，判斷不相關）：[[頁面A]]

沒有找到足以回答這個問題的內容。
已查範圍：<摘要>
建議視需要自行以 Obsidian 全文搜尋查找，以上不代表沒有相關記錄。
```

- 沒有「採用進答案」的頁面時，沒有相關主題可列，【相關主題】這段省略。
- 【查詢紀錄】同上，即使沒查到答案也要附，讓使用者能判斷是「真的查過沒找到」還是「沒有認真查」；這種情況下 Read 過的頁面通常全部屬於「未採用」。
